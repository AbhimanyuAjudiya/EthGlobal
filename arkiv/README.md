# Recharge on Arkiv

Recharge keeps the plan clock on Arkiv. Every data bundle (an `entitlement`), gift escrow, receipt, challenge nonce,
campaign, agent policy and claim lock is an entity on the **rabdi testnet (chain 7794095)**, written through
`@arkiv-network/sdk@1.0.1` (`packages/adapters/src/live/arkiv-sdk.ts`, the one file that imports the SDK, and
`packages/adapters/src/live/arkiv-ledger.ts`, the mapping rules). There is no database and no cron job: a bundle is
valid exactly as long as its entity lives.

|                                     |                                                                                                                                                                                                                                                           |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Network                             | rabdi, chain id 7794095, RPC `https://rpc.rabdi.db-chain.testnet.arkiv.network/`, explorer `https://rabdi.explorer.arkiv.network`                                                                                                                         |
| Writer (`$creator` of every entity) | [`0xC3358be9F35fDF5C8e1922be7376980C93734d3c`](https://rabdi.explorer.arkiv.network/address/0xC3358be9F35fDF5C8e1922be7376980C93734d3c) (the API's key; the agent reads with a read-only client pinned to this writer)                                    |
| Entity types                        | `recharge.<type>.v1` for `entitlement`, `campaign`, `gift`, `nonce`, `receipt`, `agentpolicy`, `claim` ([`schema.md`](schema.md))                                                                                                                         |
| Reads that depend on it             | R1 every `/esim/*` request and `GET /me/:key`; R2 the agent's remaining-MB read on each tick; R3 the gift claim by namehash and card redeem by PIN key; plus the gift reclaim, which needs the escrow entity to be **gone** (`docs/ARKIV_FEEDBACK.md` §2) |

## Expiry semantics

- Each entity is created with `expiresIn` = its validity: the plan validity for an entitlement (7 d by default, reset
  on top-up), `claimBy − now` for a gift, 300 s for a nonce, 38 d for a receipt, 30 d for an agent policy.
- The SDK turns seconds into whole 2-s blocks, rounded up (`ExpirationTime.fromSeconds`). Every entity also carries a
  numeric `expiresAt` attribute (ms), and the stores treat an entity as dead at `min(ledger expiry, expiresAt)`. That
  second clock also covers the one case Arkiv cannot do: an update cannot move the ledger expiry earlier.
- After expiry `arkiv_getEntity` answers `null` (recorded live: `fixtures/arkiv/live-expired.json`, entity
  `0x73d83f38…a9dd`, 180 s lifetime). The API remembers the last-seen `expiresAt` so `/me/:key` answers 410, not 404.

## One query you can paste

All live entitlements written by Recharge, with their ledger expiry block and attributes (no access key needed for
reads). Checked against rabdi on Fri 6 Nov 2026:

```sh
curl -s https://rpc.rabdi.db-chain.testnet.arkiv.network/ -H 'content-type: application/json' --data-binary @- <<'Q'
{"jsonrpc":"2.0","id":1,"method":"arkiv_query","params":[
  "$creator = addr(0xC3358be9F35fDF5C8e1922be7376980C93734d3c) AND type = str('entitlement')",
  {"select":{"key":true,"expiresAt":true,"attributes":true},"limit":"0x5"}]}
Q
```

It returns entity `0xcfca33d17cc05a5d6697e92cb0bad014dad41747049a05cf7c52d6bb520c55e7`: the free 300 MB Orb bundle of
the real IDKit claim of Thu 5 Nov 18:53 IST (`kind: free`, `tier: orb`, `status: pending-profile`), ledger expiry at block
552025 and `expiresAt` = 1794489799365 (Thu 12 Nov 2026 13:23 UTC, 7 days after it was written). Replace
`'entitlement'` with `'gift'`, `'receipt'` or `'claim'` for the other types. The SDK builds the same string with
`and(eq('$creator', addr(writer)), eq('type', str('entitlement')))` (`toSdkWhere` in `arkiv-sdk.ts`).

A smaller sanity check, the first request in `fixtures/arkiv/live-rpc.json` (answer `0x76edaf` = 7794095):

```sh
curl -s https://rpc.rabdi.db-chain.testnet.arkiv.network/ -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_chainId","params":[]}'
```
