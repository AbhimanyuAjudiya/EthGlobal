## 5. Code-quality notes (five riskiest files)

### `packages/octroi/src/decide.ts` (636 lines, 100 % covered)

- **:3-5** The header said nothing but the nonce entity is persisted. That was false: `reserve` (:324) and `servedOnce` (:532) also write. **Fixed in this audit** (comment only).
- **:132 / :304** `DecideRequest.existingEntitlement` is read by `alreadyServed`, but no production caller sets it. `services/api/src/middleware/octroi.ts:72-80` never passes it; only tests do (`test/decide.test.ts:102`, `test/attack/replay.attack.test.ts:39`). The field is dead in production and its doc comment admits "decide() does not need it". Remove it, or mark it `@internal` for tests.
- **:336-341** `reserve()` takes today's lock, then tomorrow's, then the campaign record, sequentially and without rollback. A ledger error _after_ today's lock returns `ledger-unavailable` but leaves the human's live lock in place until `entitlementExpiresAt` (up to 30 days). The human then gets `replay` on every later free claim, although nothing was served. This fails closed (no money is lost), but it strands a real user. The fail-closed path is tested (`test/regression/redteam-wave1.test.ts`, "a claim-lock write failure fails closed"); the stranding is not. Suggested fix: release the partial reservations on the error path, or key the live lock to the campaign record so a retry can recognise its own lock.
- **:401** `campaign.id as Hex` is a cast on validated data. It is acceptable because `freeInputInvalid` ran `campaignToPayload`, but the reason deserves a one-line comment.
- **:103** The `demo:` example still names `eip155:84532` (Base Sepolia). The protocol's network list is the source of truth, so the comment is at risk of going stale.

### `services/api/src/middleware/x402.ts` (90 lines)

- **:55 versus :61/:66** The doc comment says `PAYMENT-SIGNATURE` "is decoded ONCE here", but the header is decoded twice: once by `decodePaymentPayload` (:61) and again with `JSON.parse(Buffer.from(header,'base64'))` (:66) for the depth/v1 walk. The comment is false, and the two decoders could disagree on non-canonical base64 (Node's `Buffer` is lenient). Fix: have the codec return the parsed tree, or correct the comment.
- **:20** `/^maxamount(?:required)$/`: the non-capturing group does nothing. The pattern exists to keep the v1 field name out of the source so the project's own semgrep rule stays quiet. Prefer a plain literal with `// nosemgrep: recharge-x402-v1-primitive — this is the refusal`. Writing code to dodge your own scanner is a smell judges notice.
- **:66** `JSON.parse` here is safe only because the codec already validated the header. The ordering is load-bearing, so state it in the comment.

### `services/api/src/middleware/octroi.ts` (236 lines)

- **:221-231** `resumeIntent`'s `catch` turns _any_ non-`already_verified` error into `invalid_proof` (4xx), including network or verifier outages. A World outage during a T-24 recovery tells the user their proof is invalid instead of returning 503 `personhood_unavailable`, and a user who rescans spends a second one-time proof. Fix: rethrow adapter `unavailable`/transport codes as 503.
- **:226-227** The inner `throw fail('invalid_proof')` is caught by the `catch` two lines below and replaced by `fail('invalid_proof', {detail:'intent_proof'})`. The inner throw is indirection that only works by accident. Return a sentinel or move the nullifier check out of the `try`.
- **:166-169** When `admission.take` refuses because slots are held _in flight_ (not spent), the error is `budget_exhausted` or `hourly_cap`, chosen by which static bound is smaller. Under a burst, users can be told "budget exhausted" while budget remains. Consider a distinct `busy`/429 with `retry-after`.
- **:188** `firstResponse` duck-types `proof.responses[0]` with an `as` cast. `PersonhoodProof` should expose a typed accessor in `@ethglobal/protocol`.

### `services/agent/src/tick.ts` (269 lines) and `services/agent/src/lock.ts` (212 lines)

- **tick.ts:52 / :157** `lastNotice` is optional, and when it is absent `:157` creates a throwaway `new Map()` each tick. The "notify on change, not every 5 s" guarantee then silently disappears (production sets it at `deps.ts:200`, so this is latent). Make the field required. No test covers the dedupe (`grep lastNotice services/agent/test` → 0).
- **tick.ts:100 / :237-243** `now` is captured at tick start and reused for the `buy` journal entry, which is written after the buy and HCS submit (seconds later). Journal timestamps understate purchase time; `deps.now()` is already used for `markDone` at :220.
- **tick.ts:201-205** If `journal.write` throws inside the `catch`, the original buy error is masked. Use a best-effort write: `await …catch(() => {})`.
- **lock.ts:139** `Math.random()` backoff. It is harmless but blocks semgrep (AUD-03). Use `crypto.randomInt(1, 5)`.
- **lock.ts:9-10 / :144** The header says a holder that lost its lock "never acts on what it wrote". `held()` narrows that window but cannot close it: a holder can pass `held()` and then stall for more than `LOCK_STALE_MS` (10 s) before acting. Say "re-checks" rather than "never".
- **lock.ts:166** Staleness by `!pidAlive(pid)` assumes one PID namespace. Two containers sharing `AGENT_STATE_DIR` would break each other's live locks. The header says "one host"; add "one PID namespace (not across containers)".

### `packages/contracts/src/DataDrop.sol` (346 lines)

- **:101** NatSpec says the owner "may only `setAttestor` and `associateHts`". The owner can also call `setLedgerSponsor` (:227) and transfer ownership. The contract header :13-18 likewise omits the ledger-sponsor allow-list. The comment is wrong in an access-control document that auditors and sponsors will read. Not edited here because NatSpec changes the metadata hash and therefore the deployed bytecode.
- **:166 and :342** "block.timestamp / 3600 < 2^64 for ~2^76 years" is wrong: 2^64 hours is about 2.1 × 10^15 years, or 2^51. The conclusion holds; the number does not.
- **:153** `token.balanceOf(this) - before` underflows to `Panic(0x11)`, not `BudgetNotReceived`, if a hostile token's balance _drops_ during `transferFrom`. The behaviour is safe (it reverts) but contradicts the "API decodes reverts by name" contract at :158. Compare the values before subtracting.
- **:289-294** `isHtsAssociated` returns `true` when the token gives no answer. This is a fail-open read-back that the deploy script trusts. It is documented as `[verify Wed]`; keep it on the Wednesday checklist.
- **Tests.** The contract is strong: 210 forge tests, invariants at 256×64, slither clean at Medium. The `isHtsAssociated`-returns-false path is covered only by `test/regression/T10_DeployChainGuards.t.sol`. No gap found in `claim`/`refund`/`pause`.

## 7. Residual risks the team must disclose

1. **No testnet was ever reached from the build sandbox.** Every live adapter (World ID v4 verifier, Arkiv rabdi, Hedera HCS/HTS, x402 remote facilitators, eSIM Access, ENS) has only run against mocks or recorded fixtures. Anvil (31337) is the only chain exercised. Each `[verify Wed]` marker in the code (for example `DataDrop.sol:35,39,267,285`, `decide.ts:476`, `arkiv-sdk.ts:4`, `esimaccess-reseller.ts:438`) is an untested assumption.
2. **Fixtures were authored from vendor docs, not recorded.** `fixtures/**` and `docs/vendor/API-FACTS.md` describe vendor behaviour as documented, and the docs are sometimes missing (for example, "docs show no schema" for the eSIM Access webhook). Shapes may differ on the day. `scripts/record-fixture.ts` exists to replace them.
3. **Single API writer process.** Replay and quota guarantees (consumed-nonce cache, admission slots, intent store) are per-process. The ledger-level create-if-absent locks cover cross-process replay, but admission sizing (RT-A-03) and the nonce fast path assume one writer. Running two API replicas is unsupported.
4. **Android install path is unverified on a device.** The Android flow copies the activation code and walks Settings by hand (no deep link; the screen says "unverified on your device — test Wed"). The iOS universal-link path is equally untested on hardware. LTE attach time ("1–3 min") is a vendor claim.
5. **Lockfile refresh on Thursday (RT-P-04).** Until `pnpm-lock.yaml` is regenerated (with `minimumReleaseAge: 4320` honoured), CI cannot run any job, so none of the green results above are reproduced by CI. They were produced on this machine with workspace links. The refresh changes the resolved dependency tree a day before kickoff, and every gate must be re-run after it.
6. In addition:
   - **Anvil CORS (RT-W-05 residual):** in MODE=local any page on the machine can reach Anvil's RPC. Demo machines must not browse untrusted sites while the stack is up.
   - **The attestor is a hot key.** Its theft is bounded by the per-hour drain bound in `DataDrop.sol:30-31`, not prevented.
